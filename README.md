# NSFW 占位符反混淆还原器 (astrbot_plugin_nsfw_restorer)

专门用于规避上游大模型提供商（如 Google Gemini / Vertex AI 等）敏感词过滤与 400 拦截的 AstrBot 输出层插件。

---

## 📌 解决的核心痛点

在进行无拘无束的情感与亲密创作时，上游 API 经常会因为检测到敏感生理词汇或直白描写而触发 400 报错、返回空消息或封禁请求。

本插件利用 **占位符混淆 + 后端无损反混淆还原** 的设计范式：
1. **上游生成阶段**：模型在生成文本时使用约定的安全占位符（例如用 `[§p§]` 代表肉棒，用 `[§v§]` 代表小穴）；
2. **网关审查阶段**：发往和来自 API 的上下文均为代号字符串，无法被关键词规则命中，畅通无阻；
3. **输出拦截阶段**：在 AstrBot 准备将消息发送给用户前的 `@filter.on_decorating_result()` 最终阶段，插件自动将所有文本组件中的占位符无损替换回真实大白话，呈现在用户终端上的依然是毫无阉割、字字到肉的真实文本。

---

## ⚠️ 使用前必读：两端配合机制（极其重要！）

> **插件不是魔法！它是「上行脱敏 + 下行还原」。模型不知道代号，照样会被 400 打回来。**

### 接入步骤：

1. **保持 `auto_inject_prompt` 开启（默认就是开的）**。
   请求发出前，插件会在 `req.system_prompt` 尾部追加一份英文合规掩码协议。
   注入头只写 `span k7m` 这种乱码编号，键本身也是 `[§k7m§]`，不写能对上词的英文。
   **不要**再把明文对照表抄进人设。整段 Request（含 system instruction）会一起过前置分类器。

2. **上行也会洗历史，并且先洗 `req.system_prompt`**。
   人设卡、别的插件写进人设的明文，会先换成 token，再追加英文协议头。
   `req.prompt`、`req.contexts` 的 `content`，以及 `tool_calls` / `function_call` 里的 `arguments` 字符串同样出门前替换。
   「中出」「灌满」「肉穴」「白浆」「肉刃」这类变体归约到已有 token，不新开占位符。
   单字和日常动词（干、做、亲、含着、顶到）故意不收，避免把技术对话切碎。

3. **必须关闭 AstrBot 的流式输出（Streaming）**。
   框架对流式中途包不会调用 `on_decorating_result`，占位符会先被推到前端。
   插件只在收到 `STREAMING_FINISH` 时打一条警告，拦不住已经发出去的片段。

4. **在 AstrBot 控制台查看日志**：
   上行命中时打印：`[NSFWRestorer] 上行链路已成功脱敏混淆 N 处明文词汇`
   下行还原时打印：`[NSFWRestorer] 下行链路成功还原 N 处占位符为真实直白词汇`
   两行都没有，先看插件是否启用、映射表是否为空。

## ⚙️ 配置说明 (WebUI 原生支持)

插件附带标准 `_conf_schema.json`，已无缝接入 AstrBot 控制台面板。进入 **插件管理 -> astrbot_plugin_nsfw_restorer -> 配置** 即可直观操作：

| 配置项 | 类型 | 默认值 | 作用说明 |
| :--- | :--- | :--- | :--- |
| `enabled` | `bool` | `true` | 是否全局启用上行脱敏与下行还原 |
| `auto_inject_prompt` | `bool` | `true` | 是否在请求前注入英文合规掩码协议。关闭后模型不会主动使用 token |
| `log_restorations` | `bool` | `true` | 是否在控制台输出上行脱敏与下行还原的命中次数 |
| `mappings` | `dict` (Key-Value) | 见下表 | 占位符与目标词汇的映射字典。Key 是 token，Value 是还原后的明文。可在 WebUI 里改 |

## 🛠️ 自定义与拓展

在 AstrBot 管理面板中，你可以随时往 `mappings` 里添加你需要的任何映射，比如：
- Key: `[§c4x§]`  ->  Value: `宫颈`
- Key: `[§x9z§]`   ->  Value: `假阳具`

插件支持热重载，修改保存后立即生效！
