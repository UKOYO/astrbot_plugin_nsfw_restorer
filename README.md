# NSFW 占位符反混淆还原器 (astrbot_plugin_nsfw_restorer)

专门用于规避上游大模型提供商（如 Google Gemini / Vertex AI / Claude / OpenAI 等）敏感词过滤与 400 拦截的 AstrBot 双向全链路管道层插件。

---

## 📌 解决的核心痛点

在进行无拘无束的情感、互动与亲密创作时，上游大模型 API 往往配备了严苛的前置文本分类器（Prompt Filter / Safety Settings）。只要请求体（包括 system instruction、聊天历史上下文、当前输入、工具调用参数）中出现敏感生理词汇或直白描写，就会立刻触发 **400 Bad Request**、内容审查拦截、拒绝回复或输出空白。

本插件利用 **上行全链路无害混淆 + 下行最高优先级无损反混淆还原** 的双向管道设计：
1. **上游请求（出网前）**：将所有人设 Prompt、聊天上下文历史、多模态部件以及工具参数中的直白词，全部静默置换为抽象掩码 Token（如 `[§v4c§]`、`[§m7t§]`）；
2. **模型生成（网关层）**：模型在经过插件自动注入的掩码协议引导下，生成包含安全 Token 的文本，网关分类器只看到普通代号，彻底规避关键词审查，通行无阻；
3. **终端展示（落地前）**：在 AstrBot 准备将消息发送给用户前的 `@filter.on_decorating_result()` 阶段（挂载最高优先级 10000），插件以瞬时速度将所有 Token 替换回真实生动词汇，呈现给用户的依然是字字到肉的真实文本。

## ⚙️ 核心工作逻辑架构

```
【用户输入 / 历史记忆 / 人设Prompt / 工具参数】
                      │
                      ▼
 ┌──────────────────────────────────────────────┐
 │ on_llm_request (优先级: -1000，出网前最后防线)   │
 │ 1. 递归扫描 Prompt、Contexts、TextPart、Tools │
 │ 2. 匹配敏感词/变体，全部脱敏替换为抽象 Token    │
 │ 3. 在 req.system_prompt 尾部注入无害编码协议   │
 └──────────────────────────────────────────────┘
                      │
                      ▼ (请求体全程为抽象代码，无任何明文敏感词)
              【上游 API / Gemini】
                      │
                      ▼ (模型使用 Token 正常输出上下文)
 ┌──────────────────────────────────────────────┐
 │ on_decorating_result (优先级: 10000，落地前) │
 │ 1. 先于 TTS、消息渲染等所有下游插件拦截       │
 │ 2. 带容错机制（正则兼容漏括号、空格等变体）   │
 │ 3. 毫秒级还原为直白自然中文                   │
 └──────────────────────────────────────────────┘
                      │
                      ▼
         【用户终端收到毫无阉割的真实对话】
```

### 关键设计保障：
- **上行优先级为 -1000**：确保排在所有提示词注入、记忆召回插件的最后，保证任何其他插件塞进来的新词都不会裸奔过网。
- **下行优先级为 10000**：凌驾于 TTS 语音合成（通常为 9500）和聊天记录存储之上。必须先还原成大白话，TTS 播报和聊天记录才能读到正确的自然语言。
- **自动协议注入**：无需手动修改角色人设卡。插件会在每次请求前动态将协议挂在 `system_prompt` 末尾，既不污染原始人设，也不会因上下文轮数过多而被裁剪淘汰。

## ⚠️ 使用前必读与注意事项

1. **必须关闭 AstrBot 的流式输出（Streaming）**：
   - 框架对流式中途推送的 Chunk 不会触发完整生命周期的 `on_decorating_result`。如果开启流式，模型吐出的代号可能会在还没还原前就被推到前端。请在 AstrBot 设置中关闭流式输出。
2. **严禁在人设卡中直接写明文对照表**：
   - 很多用户习惯在 Prompt 里写“请用[§xxx§]指代XX”，这是**绝对错误的**！因为上游 API 会审查整段 Request（包括 system instruction），你在人设里写明文对照表等于直接送人头，直接触发 400。所有的协议注入全交给插件的协议头即可。
3. **查看控制台日志确认运行**：
   - 上行脱敏时输出：`[NSFWRestorer] 上行链路已成功脱敏混淆 N 处明文词汇`
   - 下行还原时输出：`[NSFWRestorer] 下行链路成功还原 N 处占位符为真实直白词汇`

## 🛠️ 自定义词汇添加教程

你可以根据自己的场景需求，随时扩充需要保护和还原的词汇。

### 方式一：AstrBot WebUI 面板（推荐，简单直观）

1. 打开 AstrBot 控制台，进入 **插件管理**；
2. 找到 `astrbot_plugin_nsfw_restorer`，点击 **配置**；
3. 展开 `mappings` 字典：
   - **键 (Key)**：自定义的占位代号。**格式要求：** 必须使用 `[§...§]` 包裹（例如 `[§c4x§]`、`[§a9b§]`），中间建议采用 3 位由小写字母+数字组成的随机乱码，严禁使用拼音或英文单词（如 `[§roubang§]` 或 `[§penis§]` 会被部分 API 的英文审查命中）。
   - **值 (Value)**：还原后的目标真实明文（例如 `宫颈`、`假阳具`、`乳夹`）。
4. 点击保存配置。插件内置热重载机制，保存后立刻生效，无需重启 AstrBot！

### 方式二：修改配置文件

直接编辑插件的数据配置文件（`data/plugins/astrbot_plugin_nsfw_restorer/config.json` 或 AstrBot 对应的插件配置）：
```json
{
  "enabled": true,
  "auto_inject_prompt": true,
  "log_restorations": true,
  "mappings": {
    "[§k7m§]": "肉棒",
    "[§v4c§]": "小穴",
    "[§c4x§]": "子宫颈",
    "[§u9w§]": "爱液"
  }
}
```

### 💡 自定义词汇最佳实践
- **词汇粒度**：只添加容易触发风控的**名词**（器官、分泌物）和**强敏感复合动词**（内射、潮吹、中出）。不要添加日常单字（如“干”、“做”、“亲”、“摸”），以免日常技术交流或正常闲聊被误伤切碎。
- **变体处理**：插件内部已自带中文长词优先匹配逻辑。对于同义词（如“肉茎”、“肉刃”、“阳具”），可以直接映射到同一个 Token（如 `[§k7m§]`），无需为每个近义词造新 Token。
